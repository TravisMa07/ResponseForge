# RF-01: contracts and pure policy

Issue: [#1](https://github.com/TravisMa07/ResponseForge/issues/1). Base: `b6a44d6` on main, including merged PR #10. Integration owner: primary agent. Status: expectation freeze; contracts/tooling only. No API, storage, provider implementation, Docker or endpoint operation is delivered here.

## Contract v1

One package, Python >=3.12, Pydantic v2. Public imports come from `responseforge.contracts`; protocols from `responseforge.providers`; policy from `responseforge.policy`. Every wire model inherits `Contract` with `schema_version: Literal['1.0']='1.0'`, forbidden extra fields and frozen attributes. Strings used as identities must be nonempty and whitespace-free at the edges. Collections use tuples for immutable scope. Datetimes accept aware ISO strings or aware datetime objects, normalize to UTC, and reject naive timestamps and numeric epochs. Booleans and identifiers must not coerce from other scalar types. JSON round trips and JSON Schema generation are supported; no claim of HTTP OpenAPI until RF-02.

Names below are the frozen Python attributes (required unless default shown). `Id` means validated string. `UtcDateTime` is the shared aware-UTC type. Modes are `replay|live`. Incident states use uppercase enum values matching the architecture. Other enumerations use lowercase values.

- `EndpointRef(endpoint_id: Id, hostname: Id, agent_id: Id|None=None)`; full equality binds identity, including agent ID.
- `Provenance(source: Id, source_ref: Id, sha256: 64 lowercase hex, original_event_ids: tuple[Id,...])`; at least one original event ID.
- `Alert(alert_id: Id, mode: Mode, source: Id, scenario_id: Id, endpoint: EndpointRef, event_time: UtcDateTime, ingested_at: UtcDateTime, rule_id: Id, severity: low|medium|high|critical, provenance: Provenance, evidence_refs: tuple[Id,...]=())`. Dedup identity is `(mode, source, scenario_id, alert_id)`; original event time may predate or exceed ingestion time and is not silently rewritten.
- `Incident(incident_id: Id, alert_id: Id, mode: Mode, scenario_id: Id, endpoint: EndpointRef, status: IncidentStatus=RECEIVED, priority: severity, assessment: Id, created_at: UtcDateTime)`.
- `Evidence(evidence_id: Id, incident_id: Id, mode: Mode, endpoint: EndpointRef, observed_at: UtcDateTime|None, collected_at: UtcDateTime, availability: available|unavailable, provenance: Provenance|None, unavailable_reason: Id|None, classification: public|sensitive='sensitive')`. Available requires observed time and provenance, no unavailable reason; unavailable requires reason and must not carry provenance. Data content belongs to RF-03, not an arbitrary wire command field.
- `Enrichment(enrichment_id: Id, incident_id: Id, indicator: Id, provider: Id, queried_at: UtcDateTime, status: success|unavailable|timeout|failed, result: str|None=None, error: str|None=None)`; successful results require nonempty result, other statuses require nonempty error and no result.
- `PlaybookRun(run_id: Id, incident_id: Id, workflow_id: Id, workflow_version: Id, correlation_id: Id, started_at: UtcDateTime, ended_at: UtcDateTime|None=None, status: running|succeeded|failed|timeout)`; only running has no end; end cannot precede start.
- `ActionType`: `terminate_process|quarantine_file|block_indicator|isolate_host|unisolate_host|disable_persistence|test_marker`. No shell command action or arbitrary arguments. `ActionTarget(endpoint: EndpointRef, resource: Id)` scopes the exact process/file/indicator/marker. RF-02 resolves resources through server allowlists; an identifier is never executable content.
- `ActionProposal(proposal_id: Id, incident_id: Id, mode: Mode, target: ActionTarget, action: ActionType, rationale: Id, risk: non_disruptive|disruptive, created_at: UtcDateTime, expires_at: UtcDateTime, idempotency_key: Id)`; positive TTL at most 1 hour. Only test_marker may be non_disruptive; other actions must be disruptive. Every proposal requires approval in this initial conservative policy.
- `Approval(approval_id: Id, proposal: ActionProposal, approver_id: Id, decision: approved|rejected|cancelled, decided_at: UtcDateTime, expires_at: UtcDateTime)`; proposal snapshot binds ALL fields, approval expiry > decision time and <= proposal expiry; decision >= proposal creation.
- `ActionCapability(provider: Id, provider_version: Id, mode: Mode, action: ActionType)`; capabilities are supplied by trusted adapter configuration, never by an alert.
- `VerificationResult(status: pending|verified|failed|timeout|unsupported, simulated: bool, verified_live: bool, checked_at: UtcDateTime|None=None, detail: Id)`; simulated and verified_live cannot both be true; verified_live requires verified status and checked time; verified requires checked time.
- `ActionExecution(execution_id: Id, proposal_id: Id, incident_id: Id, provider: Id, mode: Mode, dispatch_state: pending|dispatched|acknowledged|uncertain|failed, requested_at: UtcDateTime, updated_at: UtcDateTime, verification: VerificationResult, error: str|None=None)`; update >= request; replay requires simulated=true and verified_live=false, live requires simulated=false; verified effect requires acknowledged dispatch; uncertain/failed require error. Dispatch success alone is never an effect claim.
- `AuditEvent(event_id: Id, incident_id: Id, correlation_id: Id, actor: Id, operation: Id, occurred_at: UtcDateTime, detail: Id)`; detail is a sanitized summary, no unbounded raw payload.
- `CaseReadiness(evidence_refs: tuple[Id,...], known_gaps: tuple[Id,...], proposal_ids: tuple[Id,...], no_action_reason: Id|None=None, audit_event_id: Id)`; evidence refs nonempty and exactly one of proposals/nonempty no-action reason. Empty gaps explicitly means none known. RF-02/03 verify references actually resolve within the case.
- `MetricEvent(event_id: Id, kind: alert_accepted|case_ready, incident_id: Id, alert_id: Id, correlation_id: Id, scenario_id: Id, mode: Mode, revision: Id, environment: Id, occurred_at: UtcDateTime, readiness: CaseReadiness|None=None)`; readiness required only for case_ready. Timestamps are server receipt/ready times; link both by incident, alert and correlation IDs. RF-09 aggregates paired events, failures and sample count; elapsed time is separate from hands-on analyst minutes. No performance or time-savings claim here.
- `CollectionRequest(incident_id: Id, mode: Mode, scenario_id: Id, endpoint: EndpointRef, start: UtcDateTime, end: UtcDateTime, artifact: process|network|file|persistence)`; ordered window <=24h. `CollectionResult(evidence: tuple[Evidence,...], gaps: tuple[Id,...])`.
- `ApprovedAction(proposal: ActionProposal, approval: Approval)` is an internal carrier, not an authorization token. Construction alone never permits dispatch.

Providers: `AlertSource.ingest() -> AsyncIterator[Alert]` (regular method returning async iterator); async `EvidenceProvider.list_evidence(incident: Incident) -> tuple[Evidence,...]`, `collect(request: CollectionRequest) -> CollectionResult`; async `ResponseProvider.capabilities(endpoint: EndpointRef) -> tuple[ActionCapability,...]`, `execute(action: ApprovedAction) -> ActionExecution`, `verify(execution: ActionExecution) -> VerificationResult`. No implementation or fallback.

## Pure policy boundary

`PolicyError(ValueError)` for denials. `validate_transition(current: IncidentStatus, requested: IncidentStatus, *, reviewed: bool=False) -> None` permits only RECEIVED→TRIAGING; TRIAGING→INVESTIGATING; INVESTIGATING→AWAITING_APPROVAL or RESOLVED; AWAITING_APPROVAL→RESPONDING or RESOLVED; RESPONDING→CONTAINED/RESOLVED/FAILED; CONTAINED/RESOLVED/FAILED→CLOSED only with reviewed=True. All other edges including self-transitions denied. RESOLVED permits documented no-action/denial paths; CONTAINED requires verified effect in the durable core (RF-02), never inferred by this edge validator.

Frozen server context `AuthorizationContext(actor_id: str, authenticated: bool, roles: frozenset[str], allowed_endpoint_ids: frozenset[str], allowed_actions: frozenset[ActionType])` in policy.py is constructed only by trusted server code. Never accept it from a wire body. `validate_approval(proposal: ActionProposal, approval: Approval, *, context: AuthorizationContext, stored_approval: Approval|None, capabilities: tuple[ActionCapability,...], runtime_mode: Mode, now: datetime) -> ApprovedAction`:

1. Aware now; authenticated context has approver role; actor matches approver and endpoint/action server allowlists.
2. A server-loaded stored approval exists and equals supplied approval; equality is an oracle supplied by RF-02 storage, NOT a signed client flag. Approval decision approved and full snapshot equals current proposal.
3. proposal.created_at <= approval.decided_at <= now < approval.expires_at <= proposal.expires_at; exact expiry denied.
4. runtime mode equals proposal mode; matching mode/action capability exists. Live requires target agent_id. No live fallback. RF-02 selects the trusted provider/version capability registry and serializes dispatch with durable idempotency; this pure function performs no dispatch or dedup.

API roles reserved: source intake, analyst case/evidence/proposals/reports, approver approval/rejection, executor dispatch, workflow callback; separate credentials, default deny. Human approval identity comes from authenticated server credentials. RF-02 owns persistence and API auth/role checks, 5 minute callback timestamp window, durable nonce rejection, per-credential rate limiting (initial 60/minute), seven-day intake dedup retention and action tombstones retained for case lifetime. Unknown/timeout dispatch must reconcile before retry; never TTL-delete an uncertain action. RF-04 owns vendor transport qualification.

## Ownership and tests

Contracts agent is sole writer of `src/responseforge/contracts/**` and `src/responseforge/providers.py`. Policy agent owns only `src/responseforge/policy.py`. Test agent owns only `tests/**`; independent oracle is [frozen matrix](expectations/rf-01.md). Integration owner owns package root, tooling/lock, CI, documentation, qualification and central contract review. Agents receive this freeze commit and may not commit, push, or change other paths. No overlapping edits or stack runs. Read-only independent review follows integration.

Schema exports/examples are generated deterministically under scripts/tooling by integration after models exist. Any semantic change to this freeze requires recorded rationale and review. RF-01 acceptance is offline validation, protocols, pure policy and reproducible tooling. APIs, durable state, real execution, report provenance resolution and measured business impact remain later gates.
