## Verified vendor source basis (before code)

- Shuffle v2.3.0 source `473cc335e5fcc663006d8e5ca16af5ee71fefa68`; go.mod requires shuffle-shared v1.3.22 `f81e48ec7dfdd9fd0b94c207fb6b58535ed52a90`.
- Backend main.go routes: POST /api/v1/workflows (create assigns a NEW UUID), GET /api/v1/workflows/{id}, POST /api/v1/workflows/{id}/execute. execute body has execution_id and JSON STRING execution_argument; normal receipt success:true/execution_id/authorization. Returned authorization is a sensitive execution secret and must not be retained or echoed.
- shuffle-shared PrepareWorkflowExecution accepts client execution UUID but contains an explicit existing-ID check TODO; POST can save/requeue again. A stable ID is NOT evidence of vendor deduplication. Never automatically retry a create/start POST, even with the same ID.
- POST /api/v1/streams/results is read-only lookup despite its method; body execution_id plus API Bearer can authorize via same-org fallback. Response contains execution_id/workflow_id/(nested workflow.id), execution_argument, status and potentially sensitive raw data. Validate all correlation and whitelist output.
- Seen statuses EXECUTING, WAITING, FINISHED, FAILURE, ABORTED, SUCCESS alias. FINISHED is workflow completion, not endpoint effect. Existing core approval/action verification remains final authority.
- Official HTTP app 1.4.0 source `4a3d72091be4eb4f0c1e01fbbf62e4183d6dcc6d` logs raw header strings. Stock callback Bearer would leak. A reviewed safe callback app/image or demonstrated mitigation is required before real qualification; this work does not silently use stock logging or replace real callback acceptance with a fake.
- Default Compose has mutable latest images, backend/Orborus host socket mounts, Orborus seccomp unconfined, unrestricted management ports and insecure example TLS/secret defaults. Worker/Orborus need execution-plane Docker/Kubernetes authority; simply removing sockets is not a proven working runtime.

## Transport writer ownership and interfaces

Own ONLY `src/responseforge/integrations/shuffle/client.py`; models/__init__/coordinator owned integration. `ShuffleTransport(config:ShuffleConfig, *, transport:httpx.AsyncBaseTransport|None=None, sleep:Callable[[float],Awaitable[None]]=asyncio.sleep)`; test transport injection never disables production TLS. Methods async:

- `get_workflow(workflow_id:str)->WorkflowArtifact`: exact allowlisted UUID, GET route, Bearer header and optional Org-Id. No credentials in query. Read-only retries only timeout/network and HTTP5xx, fixed bounded backoff 0.1*2**attempt seconds, at most read_attempts. No redirect/retry for 3xx/auth/4xx; no raw error content.
- `create_workflow(document:dict[str,Any])->WorkflowArtifact`: operator-only low-level import preparation, not a public arbitrary workflow API. Validate bounded nonempty actions and JSON; POST once to /api/v1/workflows (no minimal flag), returned server UUID may be new/not allowlisted. No automatic retry. Ambiguous create cannot be blindly resubmitted; operator must locate/verify server artifact. Runtime import/bootstrap acceptance remains open.
- `start_execution(workflow_id:str,execution_id:str,argument:ShuffleArgument)->StartReceipt`: both UUIDs valid, workflow allowlisted, argument.run_id==execution_id; POST once with execution_id, execution_argument=argument.model_dump_json(), execution_source='responseforge'. Require HTTP200, strict success true and exact execution UUID; discard authorization and every other field. All network/timeout/5xx/malformed/mismatched start results are uncertain; 401/403/other4xx rejected. At most one HTTP request per call. Durable coordinator prevents repeated calls.
- `get_execution(workflow_id:str,execution_id:str,expected_argument:ShuffleArgument)->VendorExecution`: POST read-only /api/v1/streams/results body ONLY execution_id, API Bearer fallback (no execution secret retention). Validate exact execution/workflow/nested workflow IDs and parsed string execution_argument equality, known status. Same bounded read retries; unavailable/malformed/mismatch cannot become success.

Bound stream reads before parsing, never load >max bytes, reject invalid JSON/non-object/nonfinite values and contradictory success flags. No raw request/response/exception logging. Vendor unknown fields may exist but are discarded. GET/lookup stubs qualify source-derived contract only; no vendor runtime claim.

## Durable coordinator and API (integration owner)

`ShuffleCoordinator(service:CaseService,client:ShuffleTransport,bindings:dict[str,WorkflowBinding])`; async `start(incident_id:str,workflow_id:str,run_id:str,actor:Principal)->DeliveryRecord`, `reconcile(incident_id:str,run_id:str,actor:Principal)->DeliveryRecord`. Analyst role/full canonical endpoint/current mode checks; workflow must be allowlisted and have reviewed binding. Trusted workflow hash/version, origin and original argument immutable across restarts. Only a reviewed non-disruptive workflow may be configured; source data never chooses arbitrary URL/template/action. Core policy still controls disruptive actions.

Store outbox records in existing `callbacks` document collection under `shuffle:<run_id>` (tagged record_type), no schema migration or RF-01 wire change. In one core SQLite transaction register/bind PlaybookRun and insert reserved delivery BEFORE start I/O, audit `shuffle_reserved`. Duplicate returns stored record without a second start request (even across restart/crash); changed incident/workflow/version/origin/hash/argument denied. Never hold DB transaction across await. Preflight GET workflow fingerprint before new reservation; exact binding must match. Recheck authority and state in reservation transaction. A crash after reservation remains conservatively reserved; no force resend exists.

Receipt accepted changes delivery to accepted; rejected marks run failed; ambiguous start records uncertain with running run. Reconcile ONLY get_execution for original UUID; no start/import. Running/WAITING leaves running; FINISHED/SUCCESS records workflow succeeded, FAILURE/ABORTED failed. Audit sanitized events. Terminal existing run/outbox cannot be overwritten by stale/conflicting observations. Workflows never imply contained/resolved incident or endpoint effect. Authenticated callback route continues core role/nonce/timestamp/exact correlation enforcement; no bypass. Real callback credential handling remains an explicit runtime gate.

Settings adds optional shuffle_config and shuffle_bindings default empty, no automatic connection/start. API `POST /v1/incidents/{id}/shuffle/start` body `ShuffleStartRequest(workflow_id:UUID,run_id:UUID)`; `POST .../shuffle/reconcile` body `ShuffleReconcileRequest(run_id:UUID)` returns DeliveryRecord. Actor from server auth only; no raw vendor bodies or secrets returned. Client injection only through explicit create_app argument `shuffle_transport:httpx.AsyncBaseTransport|None=None` for offline qualification. Reports continue safe projection and exclude private delivery metadata.
