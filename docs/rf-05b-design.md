`build_workflow(kind:PlaybookKind, task_app_id:str, callback_app_id:str)->dict[str,Any]` generates an importable native workflow with deterministic UUID5 node/branch IDs, no workflow ID until assigned. `validate_workflow(document:dict, kind, task_app_id, callback_app_id)->None` checks the exact executable topology/metadata/branch predicate, allowing only documented harmless vendor defaults. All tasks have absent/[]/null empty parameters only. Callback fixed outcome=succeeded,delay_seconds=0. Fixed environment ResponseForge; root start Prepare, no triggers/variables/auth/URLs/commands; exit_on_error=true. ## Completion, authority and bootstrap

A domain graph's final callback cannot establish success if any required native task is missing, failed, duplicated or inconsistent. Add source-bound task proof before exposing successful callback_status: Prepare/Gate must be nativeSUCCESS, exact TaskResult correlation; Dispatch SUCCESS for ready|uncertain, otherwise SKIPPED; all kinds agree. Failed/incomplete task proof leaves coordinator uncertain/running even if vendor FINISHED and static Callback succeeded. Core node/vendor/native callback agreement and endpoint verification remain independently required. Legacy callback-only RF04 graphs remain compatible.

Worker allows only the existing callback plus exact tasks app/version/action enums, still one immutable trusted image/read-only secret volume and fixed Python module command (pilot app versus tasks). Unknown apps/functions/versions and arbitrary module/image/volume/bind/mode remain rejected. Preserve every cleanup/ownership/read-only/resource/mode guard. No SDK dependency or download/activation path is added.

A fixed opt-in replay playbook FileConfig registers original local source bytes/hash, one separate mock SQLite file, ReplayEvidenceProvider, explicit workflow-kind/technical-actor binding and pinned mock1.0. Default configs unchanged; live+playbook config rejects. No arbitrary plugin loading. Domain source is a generated/read-only private replay file from a checked-in original fixture and hash, never downloaded telemetry. A boolean playbooks_enabled renderer/state flag adds only that generated file mount to core; defaultfalse stays unchanged. Preserve old endpoints/workflow bindings/cases/credentials and lab volumes while adding domain config. No approval key enters any app or workflow.

Human waiting/rejection/expiry/no-action are explicit business branches with zero response effect. An explicitly requested later workflow invocation after a separate core human decision reuses the original case/kind/source proposal/expiry and idempotent effect. It is not an automatic retry of an uncertain launch: those always reconcile the original vendor UUID. Never auto-approve in a task. Qualification harness may act as the explicitly configured synthetic human only for simulated cases, auditing that test role.

Qualification-state refinement before runtime implementation: each fresh source/image-bound journal uses a distinct source_id suffix and separate mock SQLite filename within the retained core volume. Resume within the same journal keeps original IDs/database; a changed build cannot inherit an older pass. Qualification uses a separately named synthetic human fixture credential, never app/workflow credentials or a measured real analyst. Old operator credentials/cases/volumes are preserved; selecting an old source scope for recovery is explicit, not a live/mock fallback.

Real failure matrix refinement before qualification code: a ninth original task-failure case injects a fixed503 only after authenticated prepare commits its plan/readiness, with an explicit audit marker in the opt-in lab entrypoint. Its native task must be FAILURE and coordinator uncertain, never successful even if a callback could run. This tests the independent false-completion oracle against the real worker. Faults are host-private and reset in finally; no auth bypass or arbitrary error/command injection.

Positive restart timing is after genuine terminal native receipt/audit observation and before core reconciliation. An immediate restart inside an unacknowledged mutating Prepare request is a separate fail-closed diagnostic, not transparently retried. Positive evidence establishes durable original receipt reconciliation across restart; it does not claim interrupted HTTP requests recover automatically.
