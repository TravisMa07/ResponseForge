## Pinned source and supported subset

Wazuh v4.14.10 resolves to `6e7835b4880c3210ef30e855a6bb43432be792e1`; Docker v4.14.10 remains `76ddb88b9c8b618a254a287f2684f93d3c5ac2f4`. [Custom integration documentation](https://documentation.wazuh.com/current/user-manual/manager/integration-with-external-apis.html), [pinned Integrator source](https://github.com/wazuh/wazuh/blob/6e7835b4880c3210ef30e855a6bb43432be792e1/src/os_integrator/integrator.c), [event JSON source](https://github.com/wazuh/wazuh/blob/6e7835b4880c3210ef30e855a6bb43432be792e1/src/analysisd/format/to_json.c) are primary references. Integrator parses queue JSON then serializes compact JSON/newline to its alert file: SHA here binds exact received integration delivery bytes, not guaranteed original alerts.json bytes. Native IDs are seconds.counter and are not globally unique across managers. API keys/hook destinations supplied as argv and upstream debug logging are not adopted as trusted alert configuration.

A accepts a bounded JSON object with required timestamp (aware original ISO string, including +0200), id (decimal seconds.counter, each1..20 digits), rule.id (numeric string1..10digits), rule.level (strict int0..15), agent.id (supported decimal string1..8digits, not all zero), agent.name (nonempty<=256). No universal upstream three-digit constraint is inferred. Leading zeros remain significant. Require configured agent binding and exact original agent.name==configured endpoint.hostname. Unknown agent, manager-local all-zero agent or hostname mismatch rejects. manager.name/IP, location, full_log, data, syscheck, MITRE/groups and extensions never select targets, commands, provider, credentials, URLs or workflow. Optional data is not required; commands stay inert.

Raw bytes<=262144, strict UTF-8, no BOM, duplicate keys, nonfinite numbers, escaped lone surrogates or nonobject root. At most32 levels (root=1, each nested JSON value adds1),10,000 JSON value nodes (root/containers/scalars count, object keys excluded),16,384 codepoints per key/string value. Unsupported malformed/oversized inputs reject safely without echoing raw content. Integer strings/bools/floats cannot satisfy rule.level. Severity is an explicit local triage mapping:0..6 low,7..9 medium,10..12 high,13..15 critical; it is not detector accuracy or action authorization.

Provenance source=wazuh-alert, source_ref=wazuh://<full manager hash>/alert/<identity hash>, sha256=exact raw delivery SHA, original_event_ids=(native_id,); evidence_refs=(evidence_id,). No process lineage, state, connections, response proof or extra timestamps are invented.

mapping.py interface: WazuhError(ValueError), WazuhScopeError(WazuhError) for unauthorized agent/name; project_alert(raw:bytes,config:WazuhConfig)->WazuhObservation. No I/O or secret/clock/provider/command execution. Parser limits above precede semantic projection. Config revalidation detaches mutable input. All parsing errors use fixed safe text.

## Atomic intake and proof

WazuhService(core:CaseService).intake(raw:bytes,actor:Principal)->IntakeResult checks current server configuration/live/actor scope and projects raw. Common CaseService.intake keeps existing behavior except reserved-source rejection; its original authorized transaction body moves into _intake_tx(tx,alert,actor), reused by the native service without nested transactions or a second case implementation.

One immediate SQLite transaction resolves full dedup identity (trusted manager+agent+nativeID), fixes first ingested_at, inserts common case/meta/alert/acceptance audit/metric, one sensitive available delivery-provenance Evidence and one explicit unavailable endpoint-state/lineage/effect gap, and a typed WazuhReceipt in existing callbacks namespace `wazuh-source:<incidentID>`. Receipt stores manager_id,incident_id,full original Alert,raw_json(repr=False),two exact Evidence objects and receipt_version=wazuh-alert-json-v1. No raw telemetry enters normal reports/logs/public receipts. Raw delivery retained privately under the existing local SQLite retention policy; it is not an endpoint collection engine.

An exact duplicate uses the original first receipt, never current time, and revalidates raw SHA/bytes, mapped alert, full source/endpoint/mode, immutable original evidence/receipt and common core dedup content. Same manager+agent+nativeID with any changed byte (including whitespace) conflicts409; different agents/managers remain distinct. Missing/corrupted receipt or evidence conflicts rather than repairing historical proof. Concurrent duplicates create one case/metric/evidence pair. Any insert/storage failure rolls back the entire case+evidence+receipt; retry/restart then recovers honestly. No partial accepted native case is permitted.

POST /v1/integrations/wazuh/alerts uses existing Bearer authentication/per-actor rate limits before consuming bounded streamed body, JSON media type and fixed safe 201/200 IntakeResult. Disabled404, nonpermitted actor/scope403, malformed422, oversize413, conflicting proof409, storage503. No caller-controlled mode, approval or route parameters. It starts no workflow/provider/action. HTTPS/verified transport and explicit trusted-manager sender setup remain deployment requirements; secret authentication plus durable idempotency is not a cryptographic sensor signature or fresh endpoint proof.

Report source labels complete_received_alert/wazuh-alert-json-v1 require current exact receipt/raw re-projection, original Alert and stored evidence agreement; otherwise unavailable. Existing default redaction applies. live mode reports simulated=False, verified_live=False without actual verified response proof; API health never implies an enrolled endpoint. Live dispatch stays disabled and capability-free. No replay provider substitution on live failure.
