## Durable delivery recovery

Integrator unlinks its temporary alert file after the process returns. Before any outbound request, sender therefore stores immutable exact payload.bin and typed receipt.json in a private0700 outbox/<identitySHA> directory, atomically published without replacement. Maximum1024 delivery directories, each payload<=262144 bytes and receipt<=8192; full/conflicting/unrecognized outbox refuses before network. Binding digest includes destination, exact Wazuh source configuration and CA bytes, excluding token rotation. A process-wide file lock is owned/private and checked for links; no competing process can silently redispatch the same reservation.

State prepared→dispatching (fsynced BEFORE POST)→accepted/duplicate/rejected/uncertain. Original source/bytes/binding are revalidated on every use. Existing acknowledged delivery returns cached with no network; dispatching/uncertain stays uncertain on ordinary repeat. No blind retry or reconstruction from alerts.json. resume(config,delivery_id,*,send=False,retry_uncertain=False,transport=None) uses retained bytes, and requires both explicit send and retry_uncertain for an uncertain reservation. Administrator should inspect original receiver case first; intake is idempotent, response actions are not started. Root outbox lock and atomic publication/update preserve partial-failure diagnostics rather than clearing/resetting them. No automatic retention/deletion.

Native wrapper integrator_main(argv) reads only argv[1] as the alert path and a fixed /var/ossec/etc/responseforge-sender.json configuration. Hook/API-key/options/debug/retry argv cannot override authority. enabled=False means dry-run; separately authorized manager configuration must explicitly enable delivery. Safe status/exit codes never print payload, key, destination or upstream debug material.

Pre-implementation recovery refinement: resume also accepts retry_rejected=False. Only an explicit send=True/retry_rejected=True may make one new attempt after a known4xx refusal, enabling operator-corrected token/rate-limit recovery without deleting historical outbox proof. Ordinary delivery/resume still returns rejected with no retry. All send/retry flags require actual booleans; strings cannot authorize traffic. This requirement refinement precedes its implementation/tests and does not reinterpret uncertain success. HTTPX timeouts are per transport operation; the sender additionally checks a body-read wall budget and uses bounded lock acquisition, not a production throughput guarantee.


Implementation refinements preserve the frozen boundaries: a missing outbox is not created in dry-run and is atomically created on explicit sending; private mutations reject replaceable ancestry and use checked directory descriptors for receipt updates; staging/publication entries are synced before HTTP. A failed sync is not a no-replace collision. Generated script itself is held alongside all other ACL targets; hard-link metadata and native handle link counts reject outside-file ACL mutation. Original receipts remain consistency evidence under private local ownership, not cryptographic anti-rollback. .ps1 templates enter source-build fingerprinting because they enter the wheel.
