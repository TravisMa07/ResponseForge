## Source authority and deterministic correction

The pinned [ServerAPIClient](https://github.com/wazuh/wazuh-dashboard-plugins/blob/5005c3e2213abeb5c7798f489a7304a6abb7c6d1/plugins/wazuh-core/server/services/server-api-client.ts) constructs a real HTTPS agent with `rejectUnauthorized:false`. This allows an untrusted or wrong-host server certificate instead of enforcing server identity. An added CA cannot compensate for explicit disabled verification.

| Input / behavior | Independent expected result |
| --- | --- |
| Exact reviewed source bytes and complete expected constructor/context | Produce one deterministic corrected source; certificate/hostname verification is explicit and cannot be disabled by alert/caller data |
| Wrong source revision/hash, changed bytes, missing/duplicated/moved patch anchor or already-patched input | Refuse without silently broadening matches, applying a partial patch or relabeling a different revision |
| Unchanged source outside the bounded reviewed correction | Original class methods, source notices, token/header authority and cookie helper remain intact; no unrelated refactor or process command appears |
| Source acquisition without explicit opt-in | No HTTP or filesystem publication |
| Fixed pinned source acquisition with bad status/redirect/encoding/size/hash/partial member | No complete published bundle; retained prior output is not replaced |
| Existing/conflicting target, symlink/hardlink/unsafe input or publication race | Refuse conservatively, preserve original material and publish at most one complete private bundle |
| Generated source/license/manifest output | Exact source provenance, retained upstream notice/license and explicit modification notice; raw third-party source remains local/untracked unless separately licensed redistribution is deliberately handled |

The integration owner freezes exact models/function names, selected source members, byte/resource limits, expected source identities and transformation anchors before test/production GO. Unit tests use independently authored source-shaped synthetic text and trusted original hash vectors; they do not import private downloaded source into CI or claim a synthetic snippet is the deployed vendor module.

## Actual component transport requirements

Both authentication and authenticated requests must traverse the same corrected real HTTPS transport. Caller-provided mode, headers, paths, credentials, environment proxies or redirects cannot turn that route into an insecure connection. The complete pinned class and actual pinned cookie helper must be transpiled and loaded. Logger/ManageHosts/security constructor protocols may use original fixture implementations; Axios, HTTPS agent, TLS socket/certificate checks and HTTP exchange must be real, not success stubs.

| Scenario | Independent expected observable result |
| --- | --- |
| Original fixture CA trusted at Node process startup, server certificate matches endpoint SAN | Real HTTPS authentication succeeds; original configured Basic identity is used, response token is returned and authenticated request reaches the fixture server with the original cookie-derived Bearer token |
| No fixture CA or a different CA trusted | TLS refuses before the HTTP handler can observe credentials or application data; no fallback to `rejectUnauthorized:false` |
| Trusted chain but wrong hostname/SAN | TLS hostname verification refuses before application data; chain validity alone is insufficient |
| NODE_TLS_REJECT_UNAUTHORIZED=0 in the test child | Explicit corrected agent policy still rejects an untrusted fixture server; the environment cannot restore the old bypass |
| Configured plain HTTP destination | Refuse before HTTP socket/application request; a real plain HTTP listener records zero requests |
| URL-embedded username/password or control/ambiguous destination syntax | Refuse before network; configured application credentials are not transferred to a caller-selected insecure or ambiguous URL |
| HTTPS redirect to another HTTPS/HTTP destination | Do not follow; redirect target records zero requests and authentication data is not sent there |
| Hostile HTTPS_PROXY/HTTP_PROXY/ALL_PROXY with no NO_PROXY exemption | Ignore environment proxy routing; legitimate direct HTTPS still succeeds and the proxy listener records zero requests |
| Caller supplies Authorization or other nonallowlisted headers | Preserve the original server-selected token/header authority; do not transmit forged caller Authorization |
| Expected security refusal | Error is a real loaded-client transport refusal, not a compile/import/setup error counted as a passing security assertion |

Node reads NODE_EXTRA_CA_CERTS at startup. Trust scenarios therefore use distinct actual child processes with deliberately chosen environments; mutating that environment inside an already-running Node process is not evidence of a changed trust set. The ephemeral CA/server keys and bodies are original test material under private temporary state, never committed. All listeners bind loopback and are stopped in finally. No operating-system certificate store is modified.

## Harness, red/green and evidence

Before production GO, meaningful Python red tests demonstrate missing valid source transformation/preparation against importable fail-closed scaffolds. The native harness must also expose the original pinned module's insecure certificate acceptance before certifying the corrected module. Record the failed secure assertion and actual original-module exchange separately; dependency/import/TypeScript setup failure is not that red.

The native harness records exact original/corrected source and helper hashes, Node/Axios/transpiler versions, test-policy identities, actual success/refusal counts and remaining gates. Dependency manifests/lockfiles are primary-owned; acquisition/install is explicit, uses integrity pins and disables package lifecycle scripts. Default Python CI remains independent of source/Node dependency downloads. A private native component check outside CI is attributed separately, not silently claimed as hosted full-plugin validation.

The upstream source already contains duplicate TypeScript private `_axios` declarations. Transpile-only execution is not semantic TypeScript checking or a successful complete dashboard build. Candidate Axios 1.17.0 and TypeScript 5.5.2 match inspected workspace artifacts but do not establish the actual deployed wazuh-core dependency resolution. Keep that uncertainty explicit; do not fix unrelated vendor source merely to make a type checker green.

Independent final review inspects actual private source/compiled module/fixture-server and safe aggregate artifacts, including original-to-corrected behavior, rather than only an author summary. Passing C1 source/component tests cannot remove image/runtime/credential/certificate/bootstrap/capacity/real manager/capture/Windows/endpoint gates. Owner acceptance, promotion/feature merge, hosted checks and actual merged-revision verification remain distinct.
