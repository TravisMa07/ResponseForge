# RF-07C3 independent expectations

Issue [#7](https://github.com/TravisMa07/ResponseForge/issues/7); base actual merged revision `897b88637691dfe19fcc76f49255410b4ce88daf`. These requirements precede C3 production implementation. The integration owner freezes exact artifact members, acquisition/preparation interfaces, compiled correction anchors/hashes, dependency selection, resource limits and evidence schema before test/implementation GO. ## Packaged-artifact boundary

The optional ARM64 dashboard manifest is pinned at `sha256:83560991be21e1cc50f396bd2c8281f903b9a6a33918632057294b2300cfea65`. Its selected packaged-installation payload is `sha256:77117a11f0736bfe3b558431afcbe11c1797b3b6b0ba8afbf6698e47b5e3c097`, exactly292,316,387 compressed bytes. Registry manifest/config and source Dockerfile inspection identify a packaged installation copied into `/usr/share/wazuh-dashboard`; this is a different artifact from C2's locally emitted source component.

C3 must inspect the actual shipped complete client/helper and actual selected shipped Axios dependency files. A matching top-level package version, a C2 compiler pass or an image label does not prove the installed dependency path, compiled bytes, original source correspondence or final image execution. Preserve image/config/layer identities and the actual observed relationship to source. Do not silently label an unmatched shipped module as the previously reviewed source revision.

Inspection/preparation is read-only with respect to Docker and endpoints. Preparing a private corrected-client bundle or a digest-pinned build context does not build, import, start or qualify an image. No Docker socket, management listener, privilege change, agent installation or endpoint operation follows. Deployment remains `ready=False`; full plugin/frontend/build/packaging, deployed Linux/bundled-Node execution, manager TLS/bootstrap/capacity, captured real manager data, Windows enrollment and live response gates remain separately attributed.

## Acquisition and immutable authority

| Input or condition | Independent expected result |
| --- | --- |
| No literal explicit download opt-in | No authentication request, registry/CDN request or published cache/output |
| Exact reviewed manifest/config/payload and any required later layers | Verify bounded bytes, sizes and digests before accepting their relationship; no mutable tag or nearby platform fallback |
| Invalid digest/size/media type/platform, missing required later-layer proof or changed manifest/config | Refuse without producing a complete qualified bundle or relabeling the source |
| Bad status, encoded body, truncated/excess payload, wrong hash, interrupted read or publication failure | Refuse; no complete published cache/bundle; original inputs and existing outputs stay unchanged; a corrected explicit retry can create a new complete output |
| Registry authorization or signed CDN redirect | Use fixed reviewed origins/paths and bounded redirect policy; require HTTPS and reject userinfo/unexpected hosts/ports; never forward registry Authorization to another origin |
| Credentials, registry bearer tokens, signed URLs or response bodies in errors/metadata | Do not print or publish them; retain only safe error categories and artifact identity; private diagnostics must not become tracked source |
| Caller-provided repository, URL, platform, executable path, lock or mutable revision | The public CLI has no way to broaden the frozen artifact policy or gain execution authority |

The exact selected source-specific policy is trusted integration metadata; synthetic tests may inject independently authored trusted vectors through the frozen Python interface. Default CI never downloads an image/layer or installs Node dependencies. Public source availability and a root image license are not blanket redistribution clearance: retain per-artifact terms/notices privately and keep release/compliance decisions separate.

## Bounded archive and publication behavior

The preparation path must read selected regular-file bytes directly from a verified archive descriptor; it must not call unrestricted `extractall`, materialize vendor-controlled links/devices or execute archive content. Verification followed by reopening a pathname is insufficient. Retain descriptor identity and verify consistency across the complete bounded operation before publication. Freeze compressed bytes, decompressed bytes, entry count, per-file size and total selected-output limits before implementation; the limits must accommodate inspected required notices rather than silently omit them.

| Archive or filesystem case | Independent expected result |
| --- | --- |
| Complete exact source-specific payload and selected members | Publish one complete private bundle with all selected hashes, original class/helper/dependency bytes and applicable license/notice material preserved |
| Missing, truncated, changed or ambiguous selected member | Refuse; do not substitute another path or a freshly resolved dependency |
| Absolute/traversal/noncanonical path, selected symlink/hardlink/device/FIFO or malformed archive metadata | Refuse safely before unsafe filesystem mutation; archive filenames never become commands or unchecked destination paths |
| Duplicate selected path or conflicting member type | Refuse conservatively unless an explicitly frozen source-specific semantic rule resolves it; no last-entry guess |
| Whiteout/opaque marker, selected-path ancestor replacement or later-layer override | Refuse or apply explicitly frozen verified overlay semantics; never claim a selected payload member is the final-image member while ignoring relevant later changes |
| Unselected members | Do not extract or execute them; their presence does not expand the selected namespace or resource limits |
| Too many entries, decompression/resource excess or selected-byte excess | Stop with a bounded failure and no complete published output |
| Existing output, output collision/race or unsafe/replaceable parent ancestry | Refuse without overwriting, repairing permissions of or deleting existing material |
| Input symlink/hardlink/nonregular/unowned/unsafe mode or descriptor identity/content change | Refuse; publish only from the exact verified stable bytes |
| Mid-preparation failure | Remove only owned staging state, preserve source/existing output, and permit a new complete explicit retry after correction |

A selected layer is not a reconstructed whole-image root filesystem. Any claim that later image layers leave selected members unchanged needs digest-bound inspection of every relevant later layer, including whiteouts and ancestor effects. Record excluded layers and the limitation rather than silently infer whole-image equivalence.

## Exact correction and source rights

The original compiled client and helper stay byte-identical and separately retained. Correction must accept only the reviewed original compiled identity and exact unique constructor/context; wrong source, moved/missing/duplicated anchor, already-corrected input or unexpected companion/source identity refuses. Preserve original authentication/header/cookie behavior and all code outside the bounded reviewed correction. No alert-supplied command or arbitrary code-generation input is permitted.

The correction must explicitly enforce certificate/hostname verification, shared HTTPS-only URL policy, no redirects and no environment proxy routing for both authentication and authenticated requests. Preserve default CA behavior and startup `NODE_EXTRA_CA_CERTS` semantics. A generated patch must not leave an original source map claiming to map changed JavaScript accurately. Retain the original module/map separately, then either remove the stale map under an explicitly frozen rule or produce a genuinely valid corrected mapping; record that transformation and source correspondence.

Preserve actual compiled copyright/license comments, applicable platform LICENSE/NOTICE, selected package notices and an explicit modification notice. If an artifact lacks terms or corresponding source evidence, record that gap; do not infer rights from an unrelated repository or announce redistribution clearance. Full raw/derived vendor modules, maps, dependencies, image blobs and binaries remain private/untracked.

A prepared build context has a fixed immutable base image and an exact reviewed destination for the corrected file. It must contain only reviewed bundle bytes/instructions, with no `RUN`, package installation, network download, embedded token, Docker-socket mount, privilege setting or runtime startup implied. Generated context readiness is distinct from an owner-authorized image build, measured resulting image identity and actual manager execution.

## Native artifact and dependency oracle

Load the actual shipped complete original/corrected modules and actual shipped cookie helper, not a reconstructed constructor or a new C2 Babel/TypeScript emission. Use the selected actual shipped Axios JavaScript dependency closure with recorded paths/hashes. Resolve compiler/client/helper/dependency imports only inside the explicitly audited private artifact tree; a same-version ambient package or a fixture success stub cannot satisfy this claim. Only logger/ManageHosts/security constructor protocols may use original test fixtures. Axios, HTTPS/TLS, certificate validation and HTTP exchanges remain real.

The selected Darwin host Node runtime and the image's bundled Linux executable are different evidence. Record host Node identity/version and image/binary metadata where inspected; do not imply that a macOS fixture executed the Linux image, the bundled binary or the full dashboard plugin. Preserve Node-version mismatch/setup rejection as a failure, not an alternate-runtime pass.

Retain the 13-scenario C1/C2 matrix on the actual artifact: original insecure baseline; trusted CA/matching SAN; missing CA; different CA; untrusted chain; wrong SAN; `NODE_TLS_REJECT_UNAUTHORIZED=0`; plain HTTP; embedded URL credentials; control-character URL; HTTPS redirect; HTTP redirect; hostile proxy variables.

| Observation | Independent expected result |
| --- | --- |
| Original shipped client against untrusted fixture TLS | Complete module actually loads and performs one authentication and one request HTTP exchange; record the failed secure expectation and original insecure acceptance separately |
| Corrected client, trusted CA/matching SAN | Both paths succeed using original Basic credentials and actual helper-derived Bearer authority; caller Authorization/nonallowlisted headers do not override server authority |
| Missing/different CA, untrusted chain, wrong SAN or global TLS-disable environment | Assert expected native chain/name refusal categories and zero application/credential HTTP observations on every listener |
| Plain HTTP, URL userinfo or control characters | Assert the reviewed URL-policy refusal and zero HTTP; unrelated runtime exceptions do not count |
| HTTPS or HTTP redirect | Observe initial redirect response, prohibit follow and require zero redirect-target contacts |
| Hostile proxies | Legitimate direct HTTPS succeeds and proxy listeners record zero contacts; disclose runtime-specific proxy support rather than transfer Node24 behavior to Node18 |
| Artifact/dependency/import/setup failure | Fail qualification and retain separate diagnostics; never count a generic load or dependency failure as intended TLS security refusal |

Use fresh actual child processes for startup CA variants, ephemeral original certificates and loopback-only listeners stopped in `finally`. No OS trust-store mutation or real endpoint effect is authorized by the check.

Public summaries contain safe aggregates only. Preserve failed attempts and corrected expectation rationale through history.
