## Bounded process and Docker orchestration

The process adapter must use argv without a shell, bounded stdin/stdout/stderr and a finite deadline. Invalid limits, excessive input/output, spawn failure, timeout, malformed JSON and nonzero status fail explicitly. A generic CLI error is not evidence that a resource is absent. Kill/reap only the adapter's own child process on a limit; do not equate killing a Docker client with stopping its container or undoing a build. Retain bounded private diagnostics and distinguish requested, observed, failed, uncertain and cleaned states.

The fixed native sequence is pull of the pinned parent, parent inspection, reviewed local build, derived-image inspection, creation of an unstarted fixture, pre-start containment inspection, attached interactive start with the bound input, proof validation, and ownership-checked fixture cleanup. Persist identity/reservation evidence before a command may create a resource. No process may start before actual container inspection passes.

Parent/derived validation requires the expected parent/config identity and architecture, complete ordered base DiffID prefix and only the reviewed additional filesystem layer, immutable runtime config preservation and exact run/source ownership labels. A digest-looking string or task tag alone is insufficient. Retain the derived local image for review; do not push it or remove unrelated/parent images.

Its memory counts inside the container limit. The none network permits same-container loopback fixtures, not an external connection.

Stdin is a bounded data capsule of reviewed authored scripts, original fixture certificates/keys and pinned metadata/source. Reject traversal, extra executable files, mismatched script hashes, altered nonce/source bindings, malformed encoding or excess data before executing staged code. ## Failure, recovery and ownership

| Failure boundary | Independent expected result |
| --- | --- |
| Failure before reservation or any mutating command | No new Docker resource; prior packet/output preserved |
| Build/create/start response lost or timed out | Retain an uncertain reservation; no blind repeat that may create or start another resource |
| Unsafe container inspect before start | Never start; cleanup only if actual ownership is proven, otherwise preserve/refuse |
| Invalid/native-failed/incomplete proof or nonzero exit | Never qualify; retain diagnostics and attempt only authorized owned-fixture cleanup |
| Cleanup failure or an unexpectedly running owned fixture | Do not claim complete cleanup or overall qualification; retain recoverable identity and bounded stop/remove only for that owned fixture |
| Recovery of interrupted work | Query/reconcile and clean only the exact reserved resource after engine, immutable image, name, labels and persisted nonce/source ownership match; never restart, rebuild or promote uncertain proof |
| Foreign same-prefix/name/tag or mismatched engine/labels/image/CID | Refuse deletion/stop; no global prune, broad name sweep or unrelated resource mutation |

A name prefix or labels alone are not cleanup authority. Use a durable reservation plus the created CID or narrowly reconciled reserved name/nonce/image/engine relationship; ownership failure must preserve the foreign sentinel. Recovery does not invent a successful native execution that was never completely observed.
