# RF-01 independent behavioral expectation freeze

Derived from public architecture, acceptance, issue #1 and owner requirements before production code. These are requirement-based oracles, not observed outputs. Owning interfaces: [design](../rf-01-design.md).

| ID | Input / condition | Required outcome and rationale |
| --- | --- | --- |
| C01 | Valid replay alert; aware offset event time, independent receipt time | Accept; UTC normalization preserves instant and both times |
| C02 | Unknown schema, extra command/approved flag, missing identity, empty/space identity, numeric identity, naive/numeric timestamp | Reject; source data cannot extend the command/auth schema or create ambiguous time |
| C03 | Serialize model to JSON and reload; emit JSON Schema | Equivalent object; schema declares v1 and forbids extra fields |
| C04 | Attempt mutation of proposal or nested scope | Reject; approval cannot drift with mutable proposal fields |
| C05 | Available evidence without source hash/event IDs/time; unavailable without reason or with fabricated provenance | Reject; source-linked evidence and explicit gaps are mandatory |
| C06 | Invalid SHA-256, reversed collection window, >24h collection, reversed run/execution timestamps | Reject; bounded trusted contracts |
| C07 | Zero/negative/>1h proposal TTL; disruptive action marked non_disruptive | Reject; bounded approval and no risk downgrade |
| C08 | Replay execution claiming live proof; live execution simulated; verified effect before ack; uncertain dispatch without error | Reject; no substitution or effect inflation |
| C09 | Case ready lacking source refs, audit, or decision; both action and no-action reason | Reject; review-ready requires all four components |
| C10 | Valid ready case with explicit empty gaps and proposal OR documented no-action | Accept; readiness is an explicit correlated metric, not evidence of speed savings |
| C11 | Accepted event carrying readiness; ready event lacking it | Reject; distinct event semantics; pair by alert/case/correlation/mode/scenario |
| P01 | Every frozen allowed transition | Accept; reviewed closure required |
| P02 | Every other pair incl self, skipped triage, CLOSED outgoing, unreviewed closure | PolicyError; exhaustively enumerate independent allowed pairs |
| P03 | Authentic authorized human, exact stored approval/proposal, valid time and mode/action capability | Return ApprovedAction with original scope |
| P04 | Unauthenticated, wrong role, forged actor, missing stored approval, different stored approval | Deny; never trust self-declared approved flag |
| P05 | Different proposal target/resource/action/mode/rationale/idempotency/expiry | Deny; complete snapshot binding prevents scope expansion |
| P06 | Rejected/cancelled, now at/after expiry, future decision, naive now | Deny; TTL boundary strict and deterministic |
| P07 | Endpoint or action absent from server allowlist | Deny; capability alone never grants authority |
| P08 | Unsupported action, capability wrong mode, runtime replay/live mismatch, live without agent ID | Deny; no mock fallback and no unsupported host isolation |
| P09 | Earlier failed authorization then valid unchanged request | Valid request succeeds; pure policy has no corrupting side effects |

Tests are offline and must not rely on VMs, downloaded datasets or external network. Duplicate delivery, crash/restart and uncertain dispatch reconciliation require RF-02 durable integration; RF-01 only validates outcome vocabulary and denies unsafe policy scope. A red run must expose missing behavioral validation, not only failed imports; preserve the exact command and failures in RF-01 ledger.
