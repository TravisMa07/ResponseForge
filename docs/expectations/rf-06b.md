# RF-06B independent expectations

Issue [#6](https://github.com/TravisMa07/ResponseForge/issues/6); integration-owned [design](../rf-06-design.md), [ledger](../rf-06-ledger.md), and existing [RF-06A expectations](rf-06a.md). Initial base is actual RF-06A merge `6e3ecb4ad0bec2d476529b5c3f89a276c493ed1b`. This matrix is derived before implementation from owner requirements, separately inspected pinned source fields and Microsoft's [Sysmon event meanings](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) and [Security4698 task-created event](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4698). It is independent of implementation output; the integration owner freezes exact interfaces and source selection in the [RF-06B design](../rf-06b-design.md) before test/production work.

This bounded slice establishes source-specific projection and safe case decisions. Genuine source-bound Shuffle execution and five-scenario runtime acceptance remain separately attributed. Offline tests use original synthetic XML only, never downloaded data or a daemon. No ATT&CK label establishes a malicious verdict, general detection accuracy or endpoint effect.

| Security4698 contains TaskName, creator SubjectUserName/Domain/SID/LogonId and escaped TaskContent | A created task and its configured action, attributed to the creator account | XML Author/principal is not creator proof. The original trickbot command sample remains a negative/incomplete source: no PowerShell child was recorded and its interesting cmd.exe command exceeds existing field bounds. It must not become a new positive by truncation, synthetic children or silently broadened existing fixture behavior.

## Projection and source identity

| Input / failure | Required result | Rationale |
| --- | --- | --- |
| Valid explicitly supported provider/channel/EventID tuple | Preserve event meaning, source computer, original record ID and textual times, exact raw hash and pinned source reference | Existing integrity and provenance invariant |
| Sysmon1 versus Sysmon10/11/22 versus Security4698 | Preserve an explicit event kind; collection category alone cannot imply process creation/connection/encryption | Official event meanings and source observations |
| Same record ID in Sysmon and Security channels on one computer | Distinct normalized identities while retaining each original record ID/channel | EventRecordID is channel-scoped, not global |
| Identical full original event duplicate | Count duplicate once; do not create another case/effect | Existing replay behavior |
| Conflicting original content under same source/computer/channel/record ID | Quarantine conflict; never choose content by iteration order or compare only projected fields | Original bytes bind evidence |
| Unsupported provider/channel/EventID, duplicate or ambiguous System/EventData field | Quarantine safely; preserve neighboring valid records | RF-06A fail-closed semantics |
| XML structural failure, DTD/entity/unsupported PI, invalid UTF8, byte/event/depth bound | Safe source refusal without external access, partial certified parse or source-byte disclosure | Existing untrusted input contract |
| Missing canonical identity/time or mapped value beyond existing limits | Quarantine without invented value or truncation | Existing bounds stay meaningful |
| Distinct valid SystemTime and event UtcTime | Preserve both; use documented observed-at convention and retain original precision text | Logging time and operation time can differ |
| Optional source fields absent | Preserve absence; do not create empty successful evidence to fill a schema | No fabricated target, actor, image, GUID or lineage |
| Inner task XML with recognized declaration/namespace and exactly supported action shape | Parse only inert bounded configuration fields through a dedicated safe parser | Task XML is data inside untrusted event data |
| Inner task XML malformed, entity/DTD/arbitrary PI, duplicate/multiple ambiguous Exec or action fields | Mark unavailable/quarantine according to frozen contract; never select first/last or execute it | Ambiguity cannot choose action authority |
| Raw command/configuration includes shell substitution, HTML, encoded text, credentials or URLs | No execution, decoding, interpolation or network request; default reports omit sensitive raw text | Defensive source-data boundary |
| Additional raw fields outside explicit projection | Retain in unchanged hash-bound source; do not imply complete normalized representation | Bounded projection |

`normalize_windows(raw, artifact=..., scenario_id=...)` accepts only new windows-event-xml manifests and returns windows-events-v1 origin. Its normalized IDs are full-channel:raw-record-ID, with explicit event_kind and raw original_record_id. Legacy normalize_sysmon remains format=sysmon-xml/Event1-only. `select_recorded(batch,event_ids=...)` requires a nonempty unique known normalized-ID selection from a full new-origin batch, rejects nested selection, preserves exact original events/raw hash/ref/quarantine/duplicates, records sorted selected_event_ids and derives deterministic subset source_id. Recorded provenance must remain recorded through generated alerts, evidence, core validation, cached plans and reports. Each Windows evidence item retains raw original_record_id in provenance while its evidence identity stays normalized/channel-scoped; the same raw ID may appear twice in multi-channel alert provenance and must not silently collapse. None of the new adapter paths may emit synthetic-fixture provenance for downloaded source. The RF-06A Event1-only entrypoint and original synthetic fixture behavior remain compatible; broad support is explicit/versioned rather than silently changing that existing interface.

## Narrow rule and assessment expectations

The integration design freezes these exact narrow source predicates; the independent invariants below govern them:

- `recorded_signal(event)` returns only powershell, lsass_access, task_creation, ransom_note, process_dns or None. `assess_recorded(kind, events, alert)` returns the existing strict Assessment; primary preserves detached source-alert binding and inclusive five-minute scoping before invoking it. Kind confines process, persistence and containment observations as documented.
- PowerShell alias support is explicit, token-based and inert: a recognized exact encoded-command option with an operand and the documented hidden-window option can match; substrings such as `-encoding`, `-encfoo`, text inside unrelated arguments or encoded payload contents cannot establish an option. Only documented no-argument switches and valued execution-policy options are allowed; unknown/positional launcher tokens fail closed. The original synthetic/legacy Event1 fixture rule remains unchanged.
- New recorded policy GUID identity is a nonzero standard hyphenated UUID with optional matching braces, case-insensitive and compared as UUID values. Reject unhyphenated/nil/arbitrary/whitespace identities. PID is exact positive decimal without signs/leading zeroes, at most2147483647. Do not strip source fields to manufacture validity. Distinct canonical(GUID,PID) pairs among positive same-kind anchor observations are ambiguous; repeated equivalent GUID spelling for the same PID is not a second identity.
- A PowerShell process action targets the unique recorded process-create identity at alert time, with canonical positive PID and GUID. Missing/ambiguous identity escalates with no proposal. LSASS access matches only target lsass.exe, source mimikatz.exe/xordump.exe and a valid hexadecimal mask containing VM_READ bit0x10; it always escalates with creation/lineage/memory-content gaps and no process action. Its target identity is never substituted as an action target.
- A scheduled task matches when its configured command basename is powershell.exe. It escalates with no proposal even when the name/actor are complete; missing name/actor adds gaps. The current mock does not support disable_persistence; no fake disablement or unrelated fallback action is allowed.
- File rule matches only file_create with target basename GetYouFiles.txt and image powershell.exe. DNS rule matches only dns_query plus wscript.exe/pastebin.com or powershell.exe/cdn.discordapp.com, case-insensitively. Canonical direct GUID/PID supports mock host isolation; absent/ambiguous identity escalates. File creation/lineage/encryption and DNS creation/session/download/C2-proof gaps remain explicit even with a proposal. A broad family label alone cannot propose containment. Mock isolation remains approval-gated, simulated and reversible by explicit supported rollback, with no prevention claim.
- Scope is exact source/scenario/full endpoint and inclusive documented time window. No cross-source, cross-host, cross-channel collision, process-GUID ambiguity, PID reuse, unrelated account or out-of-window observation can manufacture a complete association.
- Positive candidate, source-negative observation and incomplete evidence outcomes remain distinguishable through assessment, gaps, audit/readiness and safe reports. No-action is a decision, not missing execution proof.
- Deterministic alert selection must be documented when multiple observed candidates exist. A later true candidate cannot be paired with an earlier unrelated alert anchor merely because both share a host.

## Core, recovery and qualification boundaries

Success tests require a source-linked alert, preserved original evidence, documented gaps and decision/audit. Explicit separate human approval is required for a supported disruptive mock action. Denied/expired/spoofed decisions and unsupported capabilities have zero effects. Repeated intake/prepare/invocation reuses the original case/proposal/readiness/expiry; verified effects are not duplicated, and uncertain effects reconcile the original reservation without redispatch. Restored/cached plans must still reject changed source/ref/hash/identity/time/provider/scope.

Actual source-negative qualification must replay an explicitly documented source-bound selection. Manually editing normalized events without retaining raw hash, selection and transformation provenance cannot count as original source proof. Synthetic incomplete fixtures remain legitimate offline behavioral tests when labeled as such; they do not establish recorded-source completeness.

Five-scenario completion requires actual genuine Shuffle branch/decision/audit artifacts on source-bound rebuilt images, exact revision/environment/manifest/provenance, truthful missing evidence and effect verification, duplicates/failure/restart/uncertainty proof, report redaction and separately measured readiness/action/recovery aggregates. Offline success and source parsing alone leave that gate open. Live endpoints, dedicated-VM runtime, releases and analyst-savings claims remain separate.
