# RF-04 remaining runtime expectations

Independent freeze from owner requirements, existing contracts and inspected source, before code. [Design/interfaces](../rf-04-runtime-design.md).

- Source hash/URL/path or patch-anchor drift fails before build; no mutable SDK/app downloads, archive traversal or partial fallback. Cleanup patches eliminate foreign-resource enumeration/removal while preserving vendor workflow dispatch. Mode guards run before Docker I/O. No secret-bearing standard diagnostic output.
- Worker custom app has exact reviewed metadata/image, named read-only private volume and project/execution labels. Unknown images/actions/host binds/modes fail closed. Only self-created or verified owned IDs may be removed; no image/name-only ownership assumption.
- Both target plans use the same product logic and image set. Reject mutable images/invalid ports/relative state path/missing images. Without scoped authority no sockets or published interfaces. With authority only agreed sockets/loopback ports, no privilege/unconfined/Swarm paths or unrelated host mounts. Private backend/indexer stay unpublished; verified CA/TLS and resource ceilings are explicit.
- Bootstrap cannot overwrite secrets or follow preexisting/symlink state paths. Generated credentials are separate, files private, cert SANs match service/loopback origins, and OpenSearch retains no default user/password. Compose/workflow/action/result/error/public evidence never contains plaintext credentials.
- Fixed app config controls destination/credential/CA, action contains only typed correlation/test behavior; reject arbitrary URLs/commands/extra parameters, workflow/run mismatch and unsupported modes before callback. Once-only callback and result delivery; lost acknowledgement uncertain, never blind fresh-nonce retry. Return sanitized native result only.
- Every lifecycle mutation binds actual engine identity, Linux architecture and inactive Swarm; wrong context/engine/grant/image proof fails without mutation. Preserve volume state and unrelated assets through restart/down. No broad cleanup/prune/context change.
- Genuine success requires actual imported nonempty workflow, original UUID, reviewed graph, exact core callback audit and whole-vendor completion agreement. Actual failure/timeout/restart/lost-ack cases cannot become synthetic success. Callback-reported terminal status alone is insufficient.
- Real forged/replayed/expired callbacks are rejected; duplicate intake/start produces one durable case/vendor launch; uncertain outcomes reconcile original identities. Actual sentinel containers with broad-match command/label stay unchanged across vendor operation and teardown.
- Offline tests use injected fetch/runner/ASGI and original tiny fixtures only. Docker execution requires explicit opt-in/grant, separate artifact/command/revision evidence. No VM/endpoint or benchmark claim follows from pilot qualification.
