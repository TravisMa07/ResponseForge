# RF-04 remaining runtime expectations

Independent freeze from owner requirements, existing contracts and inspected source, before code. [Design/interfaces](../rf-04-runtime-design.md).

- Source hash/URL/path or patch-anchor drift fails before build; no mutable SDK/app downloads, archive traversal or partial fallback. Cleanup patches eliminate foreign-resource enumeration/removal while preserving vendor workflow dispatch. Mode guards run before Docker I/O. No secret-bearing standard diagnostic output.
- Worker custom app has exact reviewed metadata/image, named read-only private volume and project/execution labels. Unknown images/actions/host binds/modes fail closed. Only self-created or verified owned IDs may be removed; no image/name-only ownership assumption.
- Both target plans use the same product logic and image set. Reject mutable images/invalid ports/relative state path/missing images. Without scoped authority no sockets or published interfaces. With authority only agreed sockets/loopback ports, no privilege/unconfined/Swarm paths or unrelated host mounts. Private backend/indexer stay unpublished; verified CA/TLS and resource ceilings are explicit.
- Bootstrap cannot overwrite secrets or follow preexisting/symlink state paths. Generated credentials are separate, files private, cert SANs match service/loopback origins, and OpenSearch retains no default user/password. Compose/workflow/action/result/error/public evidence never contains plaintext credentials.
- Fixed app config controls destination/credential/CA, action contains only typed correlation/test behavior; reject arbitrary URLs/commands/extra parameters, workflow/run mismatch and unsupported modes before callback. Once-only callback and result delivery; lost acknowledgement uncertain, never blind fresh-nonce retry. Return sanitized native result only.
- Every lifecycle mutation binds actual engine identity, Linux architecture and inactive Swarm; wrong context/engine/grant/image proof fails without mutation. Preserve volume state and unrelated assets through restart/down. No broad cleanup/prune/context change.
- Genuine success requires actual imported nonempty workflow, original UUID, reviewed graph, exact core callback audit and whole-vendor completion agreement. Actual failure/timeout/restart/lost-ack cases cannot become synthetic success. Callback-reported terminal status alone is insufficient.
- Real forged/replayed/expired callbacks are rejected; duplicate intake/start produces one durable case/vendor launch; uncertain outcomes reconcile original identities. Actual sentinel containers with broad-match command/label stay unchanged across vendor operation and teardown.
- Offline tests use injected fetch/runner/ASGI and original tiny fixtures only. Docker execution requires explicit opt-in/grant, separate artifact/command/revision evidence. No VM/endpoint or benchmark claim follows from pilot qualification.

### Observed JSON number round trip

The first actual vendor execution finished, but Shuffle's Go serialization changed
integral diagram coordinates from JSON floats to JSON integers. Before correcting
artifact hashing, freeze this expectation: numerically identical integral JSON
numbers have the same graph identity at any depth; changed numeric values,
fractional values, strings and booleans retain distinct identities. No graph field
is omitted. Regression first run: one failed, four passed. This normalization
requires rebuilding the core and fresh qualification fingerprints; previous runs
remain diagnostic evidence, not qualification of the changed build.

Closer runtime inspection found autogenerated fractional coordinates0.001 become0 in the vendor execution struct. Do not normalize fractional changes away: create qualification workflows with explicit integer coordinates and retain strict full-field graph binding. The earlier differing-types observation was incomplete.

### Execution graph identity versus UI layout

A second real run showed stored coordinates10.001/10.001 while the native executed
snapshot reports0/0. Explicit integer input does not prevent Shuffle's API layout
normalization. Freeze the narrower execution identity before changing its hash:
actions' top-level `position` is UI-only diagram layout and is excluded; every
other action field, parameters (including nested keys called position), IDs,
app/version/environment, branches, triggers, variables, start and configuration
remain bound. Changed diagram placement alone must preserve identity; changed
executable parameters or nested position data must fail binding. This corrects
the earlier assumption that stored and executed UI coordinates remain identical.

The preservation sentinel must explicitly override any image-inherited project
label with `unrelated-rf04-sentinel`; lab teardown must exclude it. Inspect both
its unique sentinel key and foreign project value before/after lifecycle tests.
Observed fixture error: inherited lab label made the original sentinel invalid
as an unrelated-resource oracle. Regression first failed1 before correction;
that diagnostic attempt was interrupted and is not a qualification pass.

### Native action outcome and vendor completion

Actual success passed. Actual deliberately failing native action returned FAILURE,
but the vendor workflow status was FINISHED even with exit_on_error. FINISHED
therefore proves completion, not action success. Before implementation, require
three agreeing observations: bound terminal executed graph, exactly one native
result for the reviewed responseforge_callback1.0.0/callback node (matching action
ID/metadata), and authenticated core node outcome. Expose callback_status
SUCCESS|FAILURE|null in VendorExecution/DeliveryRecord. Missing, duplicate,
unknown or mismatched native callback results cannot finalize a run. Terminal
FINISHED/SUCCESS plus nativeSUCCESS/core succeeded can finish; terminal vendor
completion plus nativeFAILURE/core failed|timeout can fail. NativeFAILURE/core
succeeded (real post-commit acknowledgement loss) remains uncertain/running,
including when vendor status is FINISHED. FAILURE/ABORTED with nativeSUCCESS
remains conflicting/uncertain. Keep vendor_status unchanged; never relabel vendor
FINISHED as FAILURE to fit the expectation. Update positive synthetic fixtures to
include explicit native results, retaining negative missing-result tests.
