# RF-02 independent expectation freeze

Requirement origin: issue #2, architecture/state machine, RF-01 invariants, security/acceptance and owner kickoff. Defined before RF-02 code; [design/interfaces](../rf-02-design.md).

| ID | Input / fault | Required observation / reason |
| --- | --- | --- |
| D01 | Fresh file DB, reopen; unknown future/foreign DB | Initial version 1, durable data; incompatible DB fails without rewrite |
| D02 | Exception/BaseException after partial transaction; SQL-shaped keys | Full rollback, no partial documents/keys; input remains inert |
| D03 | Repeated and concurrent identical intake from multiple Store instances; restart | One case, alert, acceptance metric and audit; stable correlation |
| D04 | Same dedup ID different payload; different scenario/source/mode | Conflict for changed payload; scoped identities do not collide (wrong runtime mode rejected) |
| D05 | Missing/wrong bearer, wrong role, source spoof, endpoint spoof, arbitrary resource/action | 401/403, no mutation/effect; no raw credential/provider error/body echoed |
| D06 | Valid intake with client historical timestamps | Original times retained; acceptance metric uses aware server clock atomically |
| D07 | Forbidden/skip/self transition; unreviewed close; manual RESPONDING/CONTAINED | Deny, state unchanged; lifecycle cannot bypass dispatch/effect proof |
| D08 | Proposal exact retry; changed endpoint/action/resource/expiry/idempotency under reused IDs/keys | Retry stable; changed scope denied/conflicts, no mutation |
| D09 | Client approver identity, service caller not human/role; wrong TTL; rejected/cancelled/expired | Server actor only; deny invalid grants and dispatch, store immutable exact snapshot |
| D10 | Approval subject revoked/reconfigured between approval and execution | Executor cannot use stale authority; no provider execute |
| D11 | Valid approved action, capability wrong provider/version/action/mode; live dry-run | No dispatch on mismatch; live dry-run causes zero adapter calls, no mock fallback |
| D12 | Concurrent execute delivery and repeated delivery after restart/expiry | Exactly one provider execute invocation in controlled test; stable persisted execution and independent executor audit |
| D13 | Crash before external execute after durable reservation | Reservation survives; repeated execute never retries; reconcile calls verify only |
| D14 | Provider effect then lost acknowledgement/timeout/crash | Outcome pending/uncertain, case not contained; reconcile original result yields one effect and verified recovery |
| D15 | Provider execute/verify error, timeout, forged correlation or chronology | No secret/error payload leakage or success inflation; durable uncertain/failure outcome and audit |
| D16 | Adapter returns verified effect directly from execute | Cannot establish effect without separate verify; correct verified isolation vs ordinary response classification |
| D17 | Concurrent/stale reconcile vs settled verification | Verified result never overwritten by stale failed/pending result; no redispatch |
| D18 | Update/delete audit or metric using repository and raw SQLite | Reject; append-only records persist |
| D19 | Evidence/ready refs to another case/endpoint/mode, missing evidence/audit/proposal | Reject; valid ready event uses original correlation and explicit gaps/decision; retry emits one event |
| D20 | Forged/missing/stale/future callback time or wrong run/case/correlation/workflow | Reject without case/action mutation; callbacks never grant response approval |
| D21 | Reused callback nonce, process restart; conflicting terminal callback | Reject replay and conflict durably; valid registered terminal callback records exactly one result |
| D22 | 60 then 61 requests in same minute, restart, next minute | First 60 permitted, 61st 429; restart retains count, next minute available |
| D23 | Tampered persisted model / model_copy bypass object | Revalidation rejects malformed scope rather than trusting constructed Python objects |

Offline qualification uses temp SQLite files, in-process HTTP clients and controlled async providers. Tests inject failure at the claimed phase, count execute/effect/verify separately and reopen stores. Synthetic adapter effects are not live endpoint proof. No network/VM/dataset needed after dependency install. Behavioral red must demonstrate a real missing invariant with a functioning harness, never just failed imports.
