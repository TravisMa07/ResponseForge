# RF-06B2 independent expectations

Issue [#6](https://github.com/TravisMa07/ResponseForge/issues/6); [B2 runtime design](../rf-06b2-design.md), [ledger](../rf-06-ledger.md), [B1 expectation freeze](rf-06b.md) and [native workflow expectations](rf-05b.md). Initial base is actual RF-06B1 merge `2ff84b8c8cf44766cc91bd4c10866057d022a4e7`. Requirements below are derived before implementation from the owner scope, existing authenticated core/native contracts and independently inspected pinned source records. They are not generated from new runtime output. Integration freezes concrete interfaces before tests/production GO.

B2 must demonstrate actual recorded-source execution through genuine Shuffle, not merely normalize data or invoke core steps from a host script. Offline tests use original synthetic source bytes and controlled transports; downloaded corpus, Docker and network remain absent from default CI. Primary alone operates the authorized stack. Raw sources, subset descriptors, native executions, journals, credentials and private endpoint identifiers remain local/untracked.

## Source registration and configuration

| Input / boundary | Expected observable result | Basis |
| --- | --- | --- |
| No recorded-source opt-in | Existing original-fixture configuration/renderer and startup remain compatible; no source acquisition or mount appears | Explicit modes and old behavior |
| Explicit replay configuration with reviewed catalog artifact, exact original bytes/hash, versioned projection and selected event IDs | Register a detached immutable source snapshot with raw provenance and explicit subset identity; select only recorded events | RF-06A/B1 integrity and selection contracts |
| Live mode plus recorded mock/source configuration | Reject, never instantiate replay success as a fallback | Owner replay/live separation |
| Missing/malformed source file, symlink/nonregular path, changed manifest/hash/selection, unsupported format, invalid/quarantined source or changed bounds | Refuse startup/preparation without successful source/runtime claim or overwriting prior state | Untrusted inputs and preserved evidence |
| Multiple sources whose source ID maps to conflicting hash/origin/data or whose alert identity conflicts | Reject ambiguity rather than choose first/last or trust ordering; repeated identical source/selection under distinct operator scenario namespaces is valid | Case-source provenance is authority |
| Same scenario and full endpoint can route collection to different snapshots | Reject configuration or collection as ambiguous before evidence mutation | CollectionRequest has bounded scope, not arbitrary source authority |
| Source A and B with identical raw record IDs but distinct source/channel/endpoint/scenario | Preserve distinct original alerts/evidence; no cross-source contamination | B1 channel-scoped identity and source hash |
| Stored case originally bound to A while B is current/default | Resolve A from the exact stored original Alert, or return source unavailable; never use B as an implicit fallback | Existing exact source-alert binding |
| Unknown or forged original case/alert/source reference | Reject or explicitly unavailable, with no fabricated evidence/proposal/effect | Source data cannot confer authority |
| Registry/input dictionaries or event fields mutate after registration | Detached registered behavior remains unchanged or immutable conflict is rejected | Original source snapshot invariant |
| Restart with the same reviewed sources and durable mock state | Same source/alert/evidence/proposal/readiness/effect identities persist; seed cannot restore terminated processes or remove prior receipts | Existing replay/idempotency behavior |
| Prior configuration and diagnostic journals exist | Preserve originals and explicit restoration path; new scopes cannot reuse an older build's pass | Handoff preservation boundaries |

The frozen `ReplayRegistry(batches)` keeps immutable detached snapshots and exposes exact `resolve(Alert)`, scoped `collect(CollectionRequest)` and `list_evidence(Incident)` routing. It accepts at most33 legacy+recorded batches; Settings recorded tuple remains at most32. Same source/selection may be registered for separately named case scenarios with the same original Computer; only conflicting hash/origin/content or ambiguous routing/alerts rejects. `load_recorded_sources(RecordedConfig,mode=...)` reads local canonical source.xml/LICENSE/manifest.json only, verifies exact original integrity, normalizes and selects without fetching.

`RecordedCaseManifest` binds qualification UUID and unique profile/scenario cases; `RecordedConfig` adds the fixed container bundle root and distinct stable recorded mock path. The named recorded-mock-edr provider uses the existing MockResponseProvider logic/version/capabilities while legacy mock-edr retains its original path. Seed each exact endpoint once from the union of actual process_create PIDs across all registered recorded cases; access/file/DNS/task facts cannot become fabricated process seeds. Runtime preparation/binding must preserve legacy provider/configuration and explicitly retain both provider identities; no old uncertain execution may switch its provider or database.

The source registry/router is server-owned. Caller-controlled source/scenario/action parameters cannot select another source, endpoint, action or provider. Exact full endpoint/scenario/time scope still applies, including inclusive ±5-minute evidence windows; PID/GUID/name equality alone is not a cross-source association. Legacy single-source core paths must retain their independent expectations.

| Scenario / fault | Independent expected outcome |
| --- | --- |

| Duplicate intake/start and explicit later invocation | One original case/source proposal/readiness/expiry; no duplicate vendor start for a delivery reservation and no duplicate durable effect |
| Unknown import/start acknowledgement | Journal retains original reservation/UUID; no automatic new app/workflow/run identity or blind mutation retry |

Historic zero-effect observations may legitimately precede a later approved effect on the same case. Cache validation must compare each recorded phase's proof without asserting the current final effect count was also zero. Final unique effects and durable mock state must be independently verified across all runs; a result field cannot be its own oracle.

## Execution boundary and preservation

Preparation remains non-starting and writes only a new reviewed private source/configuration scope. Recorded-source mounts are exact generated private paths, read-only, core-only; no arbitrary host directory, new app secret mount, arbitrary plugin/command or management port. Existing native task/worker image/function allowlists, cleanup labels, TLS/authentication, graph validation and server approval authority remain unchanged.

Before actual run, primary verifies exact authorized Desktop engine/resources, inactive Swarm, reviewed immutable images/source fingerprint/configuration and loopback-only ports. Any changed production/build input needs new source-bound images and evidence. Existing pilot volumes/cases/credentials/diagnostics and journals are preserved. Unrelated sentinel identity/state must survive workload/restart/down-up; only exact checked owned lab resources are removed. No host setting/privilege/Swarm change, live endpoint action, unrelated deletion, merge or release is inferred.

## Metrics, aggregate and qualification gates

The concrete matrix frozen in the B2 design has14 distinct operator-scoped case profiles and20 genuine native phase runs: three PowerShell phases, LSASS escalation, task escalation, two note phases, two DNS phases, five source-negative phases, two rejected phases, two expired phases, callback-ACK loss and native Prepare failure. The DNS-awaiting phase carries the positive core restart proof after terminal native receipt but before reconciliation. There are3 unique verified simulated changed-effect receipts,2 expected uncertain faults and2 rejected direct execute attempts; no extra synthetic runtime case is required to pretend a missing source field exists.

Several profiles intentionally share the same real recorded Computer and process identity. Per-phase/per-case receipt/effect attribution must remain exact; a source-negative/denied/fault profile cannot create an effect even if another approved profile already changed the shared endpoint. Never require the global endpoint effect count to stay zero after another approved action, rename source Computer to isolate a test, or reset mock state. Final distinct changed receipts must total3 and repeated approved invocation must not create another.

Readiness denominator is14 unique case/readiness events (including truthful escalation and post-commit fault cases), not20 phase runs or5 source files. Source coverage denominators are5 positive source scenarios and5 negative source cases; repeated approval/fault variants are disclosed separately.

Freeze the complete case/phase matrix before runtime code. Missing labels, wrong phase/kind/source/branch/native status, boolean-as-integer counts, nonfinite or negative timing, mismatched denominators, absent provenance or unproven recovery must fail aggregate validation. An aggregate is a projection of inspected genuine artifacts, never replacement proof.

Record exact source revision/tree/image/wheel/module/patch identities, mode, environment, sample/case/phase counts, catalog/raw hashes and selection descriptors privately. Publish only reviewed redacted aggregates. Readiness count/failures/median/nearest-rank-p95 comes from required actual acceptance/readiness events; missing/invalid events are failures, not silently dropped samples. Approval→dispatch→verified times use matching case/proposal/execution chronology. Separate approval wait/harness pacing from automation durations and hands-on analyst effort. Retain the existing API rate limit; bounded host pacing is allowed but no automatic mutating retry or hidden policy increase.

Report explicit real-workflow/scenario coverage, duplicate/forbidden effect count, expected uncertain fault runs and workflow recovery proofs. Recorded-positive/negative cases, repeated phases and synthetic fault/incomplete cases have distinct denominators. No detection accuracy, throughput, analyst savings, endpoint protection or live claim follows. Dedicated-VM and live/release gates remain separate. Closes#6 is justified only after all frozen recorded-source/native acceptance, independent actual-artifact review and remaining source-specific limitations pass; owner acceptance/merge is still a separate gate.
