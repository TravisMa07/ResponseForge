## Frozen narrow rules and recommendations

`recorded_signal(event:RecordedEvent)->Literal['powershell','lsass_access','task_creation','ransom_note','process_dns']|None` and `assess_recorded(kind:PlaybookKind,events:tuple[RecordedEvent,...],alert:Alert)->Assessment` live in the pure writer's module. Primary wires only origin.windows-events-v1 through these rules; existing original synthetic/RF-06A rules stay unchanged. `make_alerts` anchors the first matching recorded signal within each existing exact scenario/full-endpoint group, high severity with `RF-RECORDED-<SIGNAL UPPERCASE WITH HYPHENS>`, otherwise low `RF-REPLAY-OBSERVATION`. Labels/scenario names cannot create signals. `assess` keeps its detached validation/exact source alert binding and inclusive±5minute scope before invoking the recorded assessment.

1. PowerShell process-create: Image basename powershell.exe plus inert token parsing of the actual command executable and launcher options. Accept exact `-enc` or `-encodedcommand` with a nonempty non-option operand and `-windowstyle hidden`; case-insensitive. Optional recognized no-argument switches `-nop/-noprofile/-noni/-noninteractive/-nologo` and valued `-ep/-executionpolicy` are allowed. Reject other positional/unknown launcher tokens and `-command/-c/-file/-f/--`; quoted script text/options after script execution switches are data, not launcher options. Support quoted executable/operand tokens without executing/decoding payload. Quoting ambiguities fail closed. Missing target GUID/canonical positive PID escalates; unique original process-create at alert time with both proposes terminate_process/process:PID. Multiple distinct target identities at the anchor escalate. Parent references are not parent events: keep missing parent gap.
2. LSASS process-access: event_kind process_access, TargetImage basename lsass.exe, SourceImage basename mimikatz.exe or xordump.exe, hexadecimal GrantedAccess with VM_READ bit0x10 set. This is a narrow recorded source/tool/access-mask indicator, not credential theft proof. Escalate with source event IDs, explicit unavailable creation/lineage/read-memory-content gaps and no process action; never invent a creation event or join another year's recording. Missing mask/unknown tools do not match this rule; source negatives are rule-negative, not proven benign.
3. Task creation: event_kind task_create with configured command basename powershell.exe. This records a configured PowerShell task (e.g.get-process), not malicious execution. Escalate with event IDs and task-execution/process-association gaps; missing name/actor adds explicit gaps. Never propose unsupported disablement or infer executed process from configuration. Explorer configured action is rule-negative.
4. Ransom-note file: event_kind file_create, target filename basename GetYouFiles.txt, Image basename powershell.exe. This is only a recorded filename indicator. A canonical direct event process GUID/PID supports a replay host-isolation proposal with connectivity/rollback impact; missing or ambiguous direct association escalates. Do not invent encryption, file contents, a shadow-copy-delete operation, or missing Event1/lineage. Include creation/lineage/encryption evidence gaps even for a simulated proposal.
5. Process-associated DNS: event_kind dns_query, Image basename wscript.exe and exact case-insensitive query_name pastebin.com, or Image basename powershell.exe and query_name cdn.discordapp.com. Canonical direct GUID/PID supports a replay host-isolation proposal, with DNS-only/no-session/no-download/C2-proof gaps; missing or ambiguous association escalates. Firefox query is rule-negative, not proof of benign behavior. QueryResults remains text, never a guessed IP target.

Canonical new GUIDs are nonzero standard hyphenated UUIDs with optional matching braces and case-insensitive comparison; arbitrary/nil/unhyphenated/whitespace values reject. PIDs are decimal1..2147483647 without signs/leading zeros. Identity ambiguity compares canonical(GUID,PID); repeated same identity is not another inferred process. Source strings are not trimmed to manufacture a match.

Assessment kind confines recommendations: process handles PowerShell/LSASS; persistence handles configured task; containment handles file/DNS. Candidate signal must be at alert time; unrelated later indicators cannot change a different case anchor. Multiple distinct direct identities at the anchor escalate; identical identity observations may co-exist without fabricated lineage. Action resources remain existing process:PID/host:endpointID; all disruptive proposals still require independent server-authorized human approval, existing capability checks/idempotency/expiry and durable verification. Replay effects stay simulated/live=false; no new provider capability or live mode is added. All results include offline reputation unavailable; source-specific gaps remain explicit. A complete orchestration with no action is an honest escalation outcome, not a fabricated effect.
