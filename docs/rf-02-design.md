## Durable store interface (storage writer)

`responseforge.storage` exports `Store(path: str|Path)`, `Transaction`, `StorageError(RuntimeError)`, `ConflictError(ValueError)`. File-backed SQLite only; reject `:memory:`. Store construction initializes/migrates an empty database atomically to application schema version 1; identify it with SQLite application_id, reject foreign populated databases and unknown future versions without modification. Enable foreign keys, WAL, busy timeout and synchronous FULL. Each `with store.transaction() as tx:` creates an independent connection and `BEGIN IMMEDIATE`; commit on success, rollback on any BaseException, close always. Never hold this transaction across await/provider I/O. Concurrent store construction and concurrent intake must serialize safely.

Generic JSON document collections are allowlisted: `alerts, incidents, case_meta, proposals, approvals, executions, evidence, workflows, callbacks, audit, metrics`. `tx.get(collection: str, key: str) -> dict[str, Any]|None`; `tx.insert(collection, key, value: dict[str, Any]) -> None` (duplicate raises ConflictError); `tx.replace(collection,key,value) -> None` (missing raises KeyError); `tx.list(collection) -> tuple[dict[str,Any],...]` ordered by insertion. Every document is JSON-encoded, detached on read. SQL parameters, never interpolated input. Store JSON cannot contain NaN/Infinity. `audit` and `metrics` append-only at both repository and SQLite trigger boundary (cannot update/delete). `tx.get_key(namespace: str,key: str)->str|None`; `tx.claim_key(namespace,key,value: str)->bool` atomically claims unique key. `tx.consume_rate(actor_id: str, now: datetime, limit: int=60)->bool` fixed UTC minute window, persistent across restart, rejects above limit. Actor ID never a token. `Store.version: int` exposes supported version. No automatic deletion: intake keys retained at least seven days, action tombstones for case lifetime, callback nonces retained; explicit retention tooling is future work.

## Runtime/auth boundary (integration writer)

`responseforge.runtime` exports frozen `Principal(actor_id: str, roles: frozenset[str], endpoint_ids: frozenset[str], actions: frozenset[ActionType], resources: frozenset[str], sources: frozenset[str]=frozenset(), human: bool=False)`; `Settings(database_path: str|Path, mode: Mode=Mode.REPLAY, endpoints: tuple[EndpointRef,...]=(), credentials: dict[str,Principal]=..., resource_allowlist: dict[str,frozenset[str]]=..., providers: dict[str,ResponseProvider]=..., provider_versions: dict[str,str]=..., live_dispatch_enabled: bool=False, provider_timeout: float=5.0, revision: str='development', environment: str='local')`. Settings validates unique actor IDs and endpoint IDs, nonempty secrets (>=32 chars), no conflicting identities, positive timeout; tokens excluded from repr. No default credentials, endpoints, actions or providers. Revalidate endpoint models at construction. Runtime settings are trusted server configuration; restart reloads changed authorities. Each actor has exact endpoint/action/resource allowlists; resource_allowlist further limits allowed resources per enrolled endpoint. Full EndpointRef equality binds canonical identity, not hostname alone.

Bearer credentials authenticated by server config; no actor/role/approval booleans accepted from bodies. Separate roles source, analyst, approver, executor, workflow. Approver must human=True. Executor identity differs from stored human approver subject; both currently authorized at dispatch. Source role additionally checks Alert.source against configured sources. All /v1 routes authenticated and persistent 60 requests/minute per actor; errors expose generic messages, never tokens, raw provider exceptions or untrusted bodies. Unknown credential 401, wrong role/scope 403, invalid schema 422, missing object 404, semantic/duplicate conflict 409, provider unavailable 503. Denials on known case are audited without supplied payload/secret text. Health/readiness expose only application status and mode, no enrolled-provider claims.

## Core service interface (core writer)

`responseforge.core` exports `CaseService(store: Store, settings: Settings, *, clock: Callable[[],datetime]|None=None)` and `ServiceError(Exception)` with `status_code: int, detail: str`. Public synchronous methods unless marked async, argument names frozen:

- `intake(alert: Alert, actor: Principal) -> IntakeResult`; IntakeResult (integration-owned Pydantic model) has incident_id, duplicate:bool, correlation_id. Revalidate all incoming model values through JSON-compatible dump then model_validate (copy/update APIs bypass validation). Mode must match settings and endpoint must equal configured canonical identity and actor scope. Dedup `(mode,source,scenario_id,alert_id)`; identical normalized payload returns same case/correlation, no new alert/case/metric or acceptance audit. Different payload under same key conflicts. Persist alert, RECEIVED Incident, case_meta `{incident_id,alert_id,correlation_id,scenario_id,mode}`, acceptance audit and MetricEvent(kind=alert_accepted, server timestamp, revision/environment) in one transaction. Severity sets priority, assessment='Awaiting triage'.
- `get_incident(incident_id: str, actor: Principal)->Incident`; `list_incidents(actor)->tuple[Incident,...]`; `audit(incident_id,actor)->tuple[AuditEvent,...]`; `metrics(incident_id,actor)->tuple[MetricEvent,...]`; `evidence(incident_id,actor)->tuple[Evidence,...]`. Analyst role/read scope; list filters unauthorized endpoints.
- `transition(incident_id: str, status: IncidentStatus, actor: Principal, *, reviewed: bool=False)->Incident`. Use RF-01 edge validator. Manual RESPONDING denied (dispatch owns it); CONTAINED requires verified isolate_host execution for this case and live proof if live; RESOLVED from RESPONDING requires a settled execution, never pending/uncertain/timeout. Atomic audit. CLOSE requires reviewed.
- `propose(incident_id: str, proposal: ActionProposal, actor: Principal)->ActionProposal`. Analyst, exact case/mode/endpoint, resource+action allowed by both actor and configuration, created_at<=now<expires_at. Case must INVESTIGATING or AWAITING_APPROVAL. Unique proposal_id and global per-mode idempotency key; identical retry returns original, scope change conflicts. Snapshot immutable; insert proposal, move INVESTIGATING→AWAITING_APPROVAL and audit atomically.
- `decide(proposal_id: str, decision: str, expires_at: datetime, actor: Principal)->Approval`. decision approved|rejected|cancelled; human approver role and endpoint/action/resource scope. Construct approver_id, decided_at and snapshot server-side; cannot accept an Approval object from API. Proposal currently unexpired; approval TTL fits proposal. First decision immutable, identical actor/decision/expiry retry returns original, contradictory retry conflicts. Audit decision. Denied/rejected cannot execute. Durable policy uses current authority after restart, not the roles recorded at approval time.
- `action(proposal_id: str, actor: Principal)->ActionView` (integration model: proposal, approval:Approval|None, execution:ActionExecution|None). Analyst/executor/approver scoped read.
- `add_evidence(incident_id: str, item: Evidence, actor: Principal)->Evidence`; analyst role, exact case/mode/canonical endpoint; immutable evidence ID globally and identical retry only. No invented collection or source completeness claim. `mark_ready(incident_id: str, readiness: CaseReadiness, actor: Principal)->MetricEvent`: all referenced available evidence, proposals and audit resolve to same case/mode/endpoint; gaps explicit. Exactly one ready metric per case, identical retry idempotent, conflicting packet rejected. Preserve intake correlation and server times. Actual evidence-source mapping/accuracy belongs RF-03.
- `register_workflow(incident_id: str, run_id: str, workflow_id: str, workflow_version: str, actor: Principal)->PlaybookRun`; analyst role, server correlation from case; running record at server time, immutable run ID retry. `callback(item: WorkflowCallback, actor: Principal, *, nonce: str, sent_at: datetime)->PlaybookRun`: workflow role/scoped endpoint, timestamp within ±300s of aware server now, nonempty nonce<=128 chars; atomically unique `(actor_id,nonce)` and exact incident/run/workflow/correlation against registered run. terminal callback status succeeded|failed|timeout only; update run/end + sanitized audit atomically. Replayed nonce rejects even after restart. Callback never authorizes response, mutates approvals or establishes endpoint effect. Same terminal result with fresh nonce idempotent; contradictory terminal callback conflicts.
- async `execute(proposal_id: str, provider: str, actor: Principal)->ActionExecution`; async `reconcile(proposal_id: str, provider: str, actor: Principal)->ActionExecution`. Detailed safety below.

Denied service operations should record sanitized audit operation `denied` separately from rolled-back mutations when a known case can be identified; authentication/rate middleware records system-scope denials. Model validation errors at untrusted boundary need no echo of input in HTTP output. Store reads reconstruct and validate domain contracts, not trusted model_construct/copy.

## Dispatch/recovery invariant

Only configured ResponseProvider objects and configured version names can be selected; capabilities returned by that adapter must match configured provider name/version and runtime mode/action. Validate caller executor scope and currently configured human approval subject with RF-01 validate_approval (stored approval and exact snapshot). Live mode defaults to denial before any provider call when live_dispatch_enabled=False; no fallback. RF-02 ships no live provider and no production mock provider; tests use controlled in-process adapters only.

After capability lookup (bounded timeout), re-read approval and state in a short transaction; if an execution already exists, return its persisted result without execute and reject changing provider. First dispatch requires AWAITING_APPROVAL. Atomically reserve ActionExecution with deterministic execution_id=`exec-`+proposal_id, dispatch_state=pending, verification pending, requested_at=server now, mode flags; move case RESPONDING; append `dispatch_reserved` audit. Commit BEFORE calling provider.execute(ApprovedAction). Once reservation exists, delivery retries never call execute again, including on another process/restart or expiry. Duplicate requests still require currently authorized executor, but return prior result without requiring unexpired approval or another capabilities call. Reservation consumes the action idempotency scope for case lifetime.

Provider execute returns correlated execution/proposal/case/provider/mode. Returned execution ID must match reserved ID; no arbitrary result can overwrite another case. Validate chronology (reserved requested_at<=provider requested_at<=updated_at<=server now; any checked_at in request/update interval) and revalidate models. Persist dispatch result; an acknowledged result must undergo provider.verify (do not trust an execute-returned effect claim by itself). Verify must return checked_at between reserved request and server now for terminal verification. Verified isolate_host means CONTAINED; other verified actions mean RESOLVED. Definitive failed/unsupported verification or failed dispatch means FAILED; uncertain/timeout stays RESPONDING and blocked from redispatch. Persist audit before and after external calls and verification.

Timeout/error during execute records uncertain with generic error and pending/timeout verification, never fake success. Crash/SystemExit/CancelledError after reservation may leave pending; this still blocks all retries. No eager startup mutation of pending entries (other workers may still be in-flight). `reconcile` uses ONLY provider.verify on the original persisted execution, never execute. Pending/uncertain may become acknowledged upon verified effect; no verification proof leaves it blocked. Bounded asyncio wait_for calls. Concurrent reconciliation must not overwrite a verified final result with stale pending/failure; read/check/write serialized. RF-03 adapters must use proposal idempotency key to query original effect; no distributed exactly-once claim.

## HTTP interface (integration writer)

`responseforge.api.create_app(settings: Settings, *, clock: Callable[[],datetime]|None=None)->FastAPI`; app.state.service exposes service for controlled test integration. Internal request/response models in runtime (not RF-01 public schema exports): IntakeResult, ActionView, TransitionRequest(status,reviewed=False), DecisionRequest(expires_at:UtcDateTime), ExecuteRequest(provider:Id), WorkflowRegistration(run_id,workflow_id,workflow_version), WorkflowCallback(run_id,incident_id,workflow_id,correlation_id,status:succeeded|failed|timeout). All forbid extras. No client-supplied actor or approval token.

POST /v1/alerts (201 new/200 duplicate), GET /v1/incidents, GET /v1/incidents/{id}, GET /v1/incidents/{id}/audit, /metrics, /evidence; POST /v1/incidents/{id}/transition, /evidence, /ready, /workflows, /actions/propose; GET /v1/actions/{id}; POST /v1/actions/{id}/approve, /reject, /cancel, /execute, /reconcile; POST /v1/integrations/shuffle/callback with X-Request-Timestamp and X-Request-Nonce. Callback naming reserves the integration path; does not claim actual Shuffle compatibility. /healthz and /readyz disclose app only. OpenAPI/docs are authenticated or disabled by default. CLI/local factory binds 127.0.0.1 only; no deployment or management exposure.

## Reviewed implementation refinements

Independent artifact review clarified required cross-record validation: schema-valid stored execution/approval snapshots must bind to the requested key, full canonical endpoint, case, mode and original provider. Canonical identity also applies to case listing. All non-None provider check timestamps, including pending results, must be in the dispatch/server interval; otherwise persist a sanitized uncertain result and allow later reconciliation. Regression tests preserve these interpretations of D05/D15/D23.

Reservation atomically retains the configured provider version in an internal `execution_provider_version` unique key; unresolved reconciliation refuses a missing/changed version rather than querying another adapter version under the same name. This refines original-provider verification without changing RF-01 wire contracts. Already verified historical results remain readable without provider I/O. Invalid model-copy objects are serialized without raw-value warnings and immediately revalidated; this prevents log leakage, not validation bypass. Tests and review validate all refinements before qualification.
